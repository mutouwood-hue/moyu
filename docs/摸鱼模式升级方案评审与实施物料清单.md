# 《挣点窝囊费》摸鱼模式升级方案评审与实施物料清单

> 文档版本：v1.0  
> 评审日期：2026-08-13  
> 评审对象：用户提供的《摸鱼计薪》产品升级方案，以及当前仓库 v1.1.0 实现  
> 建议产品名：**《挣点窝囊费》**（品牌名）/ **摸鱼计薪桌面搭子**（品类说明）

---

## 1. 结论摘要

方案的产品方向成立，而且与当前产品“把工资数字做得有趣”的调性高度一致。最值得保留的是四点：

1. 真实工资与虚拟摸鱼币永久分账。
2. 摸鱼模式成为娱乐内容入口，但不强迫用户玩游戏。
3. 商店只售卖视觉内容，不改变工资、计薪速度或游戏胜率。
4. 卡皮巴拉承担跨看板、悬浮窗、游戏、商店和收藏的统一角色。

但原方案不适合原样进入开发，主要需要做以下调整：

- **把六个一级模块压缩为四个**：看板、记录、摸鱼屋、设置。“摸鱼乐园 / 商店 / 收藏”作为“摸鱼屋”的二级页签。当前主窗口宽度只有 520–642px，六个底部导航会拥挤，也会让计薪工具显得像游戏平台。
- **第一阶段先做一条完整纵切，不同时做三款游戏和完整商城**：先完成“摸鱼会话 → 木鱼暴击 → 摸鱼币 → 购买 3 件商品 → 装备生效”，验证闭环后再增加“老板来了”和“工位钓鱼”。
- **不再用‘进入摸鱼模式 10 次’解锁皮肤**：当前实现可以反复切换刷次数，和新经济体系冲突。旧用户已解锁权益保留，后续解锁改为成就、商品或首轮迁移奖励。
- **不在切换摸鱼模式时自动弹出游戏**：当前代码会立即打开 1120×800 的“星轨弹射”，与方案中“不打扰、小游戏藏在摸鱼模式里”的原则相反。
- **现有“星轨弹射”降级为彩蛋或后续奖励游戏**：它有完整 50 关和本地进度，完成度高，但题材、窗口尺寸和节奏都不适合作为摸鱼模式的首个入口。
- **真实记录和主题基础设施应前移，不应排到 V1.3**：当前已经存在历史落盘和 CSS 变量，只需扩展数据字段、迁移机制、主题清单和装备状态。
- **数据暂不拆成五个互相独立、可能不同步的 JSON 文件**：先建立一个版本化、原子写入的状态仓库，或至少把钱包与消费流水放在同一事务域；等数据量和维护复杂度真实增长后再拆分。
- **主界面与悬浮窗的 Electron 安全模型需先升级**：当前两者使用 `nodeIntegration: true`、`contextIsolation: false`。增加商店、库存、老板键和更多 IPC 前，应先引入 preload 白名单桥接。

### 建议后的首发范围

首发不追求“内容多”，而追求一次完整且可信的循环：

```text
工作计薪
  ↓
主动进入摸鱼模式
  ↓
记录本次摸鱼会话（不自动弹游戏）
  ↓
打开摸鱼屋 → 木鱼暴击
  ↓
结算摸鱼币（工资完全不变）
  ↓
购买 3 件首发视觉商品
  ↓
装备到主界面 / 悬浮窗 / 卡皮巴拉
  ↓
回到计薪
```

这条纵切跑通后，再补齐 3 款游戏、9 件商品与收藏图鉴。

|---|---|---|

### 2.3 现状流程截图与健康度

#### 步骤 1：主看板与模式入口 — 健康度：良好，但模式定义不足

优点：工资金额、工时进度、日薪和可视化工资罐层级清楚；产品的“现实反馈”已经成立。  
问题：默认模式与工作模式目前没有可感知的行为差别；“累计摸鱼 0/10 次解锁皮肤”把模式切换本身变成可刷任务。

#### 步骤 2：切换摸鱼模式 — 健康度：需重构

![当前摸鱼模式](../qa/moyu-mode-audit/02-current-slack-mode.png)

优点：摸鱼金额与工资总额在文案上分开显示，符合双经济体系的雏形。  
问题：页面只改变标题、状态和累计文案，缺本次摸鱼计时、明确退出、游戏入口出现规则、卡皮巴拉状态与钱包。Electron 实际运行时还会立即弹出游戏，打断用户。

#### 步骤 3：皮肤解锁 — 健康度：可复用基础，规则需替换

![当前皮肤设置](../qa/moyu-mode-audit/03-current-skin-unlock.png)

优点：已有皮肤装备入口、使用中/锁定状态和主题 CSS 变量。  
问题：皮肤被放在设置页，未来购买、收藏、装备会让设置页越来越重；星轨预览只是小色块，无法表达购买价值。

#### 步骤 4：现有星轨弹射 — 健康度：游戏本身成熟，产品归属不合适

![当前星轨弹射](../qa/moyu-mode-audit/04-current-orbit-game.png)

优点：已有 50 关、键盘操作、本地最佳成绩、暂停、声音和全屏，单独作为游戏完成度高。  
问题：1120×800 窗口过大；太像独立游戏平台；与卡皮巴拉、办公室梗、摸鱼币和商店没有联系；一进入摸鱼模式就自动打开。

#### 步骤 5：悬浮窗摸鱼状态 — 健康度：基础好，核心反馈不够

![当前悬浮窗摸鱼状态](../qa/moyu-mode-audit/05-current-floating-slack.png)

优点：入口直接、金额和工时仍然清晰，窗口尺寸适合常驻。  
问题：只显示“摸鱼 ¥0.00”，没有本次时长、可选游戏入口、当前称号和角色状态；模式按钮占据的横向空间较大。

#### 步骤 6：记录页 — 健康度：结构可用，数据维度不足

![当前记录页空状态](../qa/moyu-mode-audit/06-current-records-empty.png)

优点：月度汇总和列表结构可复用。  
问题：缺工作时长、摸鱼率、游戏局数、摸鱼币收支；空状态无法解释何时会产生记录。截图为浏览器预览环境，没有读取 Electron 用户目录中的真实历史，不能据此判断用户已有数据为空。

#### 步骤 7：日历页 — 健康度：可并入记录

![当前日历页](../qa/moyu-mode-audit/07-current-calendar.png)

优点：日期选择、当日详情和月度概要已经具备。  
问题：内容量不足以独占一级导航；合并到记录页能为摸鱼屋腾出入口，又不会丢功能。

### 2.4 可访问性证据与限制

当前可见优势：主要按钮有可读名称，键盘焦点样式存在，设置中支持减少动态效果，游戏有键盘操作和暂停。  
当前风险：摸鱼模式状态主要靠颜色与短文案；游戏 Canvas 的可访问文本有限；反应游戏可能排除动作慢或无法快速按键的用户；未来声音提示必须有视觉等价物。  
本次截图不能证明完整 WCAG 符合性，也不能验证屏幕阅读器朗读顺序、全键盘焦点闭环、200% 缩放或系统高对比度，需要在实现阶段单独测试。

## 3. 对原方案的逐项调整

| 原方案主题 | 结论 | 调整建议 |
|---|---|---|
| 工资可视化 + 摸鱼陪伴 + 游戏 + 收藏 | 保留 | 计薪始终占主入口和首屏最大视觉权重 |
| 工资与摸鱼币永不兑换 | 强制保留 | 数据模型、UI 颜色、图标、文案和流水全部分开 |
| 六个一级模块 | 调整 | 改为看板 / 记录 / 摸鱼屋 / 设置；乐园、商店、收藏为摸鱼屋二级页签 |
| 默认 / 工作 / 摸鱼三模式 | 调整 | 用户只操作工作 / 摸鱼；默认、未开工、下班作为系统派生状态 |
| 进入摸鱼模式开始计时 | 保留 | 用会话模型保存开始、结束、持续时间和原因 |
| 1 分钟出现入口、3 分钟提醒 | 调整 | 首次引导可在 3 分钟解锁；解锁后每次不再强制等待；提醒每次会话最多一次 |
| 10 分钟随机事件 | 延后 | 每天最多 2 次、可关闭、不得制造损失恐惧 |
| 首发三款游戏 | 分阶段保留 | 木鱼暴击先做；老板来了第二；工位钓鱼和图鉴第三 |
| 80 件钓鱼图鉴 | 缩减 | MVP 18 件：10 普通、5 稀有、2 史诗、1 传奇；后续内容包扩展 |
| 摸鱼币主要来自互动 | 保留 | 增加幂等结算和日奖励软上限，不奖励挂机时长 |
| 每日任务 | 延后 | 闭环稳定后加入；先做固定的新手任务，避免内容运营负担 |
| 商店只售视觉 | 强制保留 | 不售工资、奖励倍率、概率或计薪相关能力 |
| 商店做小卖部 | 保留方向 | 先做轻量货架；真实“小卖部”场景需要专门插画和动效，不应由普通商品列表假装 |
| 我的摸鱼屋 | 保留 | 先作为摸鱼屋内的“收藏”页签，内容足够后再升级为场景化房间 |
| 长期称号体系 | 保留并改规则 | 不再按“摸鱼金额 / 日薪”发长期称号，改为时长、游戏和收藏成就；金额仅做当日趣味评价 |
| 老板键 | 前移到 V1 | 只隐藏本应用娱乐窗口并恢复简洁悬浮窗；不能伪装或读取其他应用 |
| 主题 token | 前移到基础阶段 | 复用现有变量，补语义 token、主题 manifest、资源引用和版本兼容 |
| 五个 JSON 文件 | 调整 | 先用统一版本化状态仓库或同事务的钱包文件；必须原子写入、备份、迁移 |
| 等级系统 | 延后 | 首发只显示余额、称号和收藏；等级不影响能力，避免 RPG 化 |
| V1.3 才做真实记录 | 前移 | 当前已经有历史，V1 即补全工作秒数、游戏局数、币流水和周统计 |
| 当前星轨弹射 | 重新归类 | 改为“实验彩蛋 / 后续奖励游戏”，不自动弹出，不进入首发核心任务 |

## 4. 调整后的产品定义

### 4.1 产品一句话

**《挣点窝囊费》是一款把真实工资进度做成轻量陪伴体验的桌面计薪工具；工作时看钱增长，休息时和卡皮巴拉玩一小局，用虚拟摸鱼币让界面更像自己。**

### 4.2 品牌命名建议

- 主品牌：挣点窝囊费
- 品类副标题：摸鱼计薪桌面搭子
- 模式名称：工作 / 摸鱼
- 虚拟空间：摸鱼屋
- 游戏集合：摸鱼乐园
- 货币：摸鱼币
- 收藏区：我的收藏

“摸鱼计薪”描述准确但偏功能名；“挣点窝囊费”更有记忆点，也与当前应用、安装包和视觉资产一致。无需在功能升级时同时承担全量品牌迁移风险。

### 4.3 不可破坏的产品原则

1. 真实工资永远可信，不能被游戏、皮肤或摸鱼币改变。
2. 所有娱乐行为都由用户主动触发，可随时退出。
3. 摸鱼模式不是考勤监控，不读取其他应用和输入。
4. 游戏单局短、失败损失低，不制造连续签到压力。
5. 商店只改变视觉和收藏状态。
6. 离线优先，本地数据默认不上传。
7. 计薪入口永远比游戏入口更突出。

### 为什么不是六个一级模块

- 当前窗口最小宽度为 520px，六个底部标签的点击目标、文字和图标会相互挤压。
- 商店、收藏必须先依赖游戏和钱包，内容早期不足，独立入口会显空。
- “摸鱼屋”把娱乐内容收纳在一个边界内，能继续强调这是计薪工具，不是游戏平台。

## 6. 模式与状态模型

### 6.1 用户可操作模式

#### 工作模式

- 正常计薪。
- 卡皮巴拉显示工作状态。
- 悬浮窗保持简洁。
- 不主动弹出小游戏提示。
- 每连续工作 120 分钟可出现一次非强制休息提醒。

#### 摸鱼模式

- 正常计薪继续进行，工资口径不变。
- 创建一条摸鱼会话，累计本次时长与对应工资展示值。
- 卡皮巴拉切换为摸鱼状态。
- 显示“摸一把”入口，但不自动打开。
- 退出模式时结算会话，不结算摸鱼币。

### 6.2 系统派生状态

- 未开工：当前时间早于班次开始。
- 已下班：标准班次完成。
- 加班：超过班次结束，继续显示现有参考金额逻辑。
- 暂停/休息：未来可选，不在首发范围。

建议隐藏现有“默认模式”按钮。为兼容旧数据，读取到 `mode: default` 时映射到工作模式，不立即删除字段，待一次版本迁移后再清理。

### 6.3 摸鱼会话规则

```json
{
  "id": "slack_20260813_153210_x7k2",
  "workDate": "2026-08-13",
  "startedAt": "2026-08-13T15:32:10+08:00",
  "endedAt": "2026-08-13T15:39:42+08:00",
  "durationSeconds": 452,
  "salaryDisplayAmount": 3.21,
  "gamesPlayed": 1,
  "fishCoinsEarned": 18
}
```

注意：`salaryDisplayAmount` 只是本次时间对应的真实工资展示切片，不进入摸鱼币钱包，也不额外增加工资。

### 6.4 提醒节奏

- 首次用户：首次摸鱼累计 3 分钟后解锁木鱼暴击，完成新手引导。
- 已解锁用户：切换摸鱼后立即可主动打开乐园。
- 每次会话最多出现一次轻提示，默认在 3 分钟时出现。
- 提示可永久关闭；老板键启用后不显示系统通知正文。

## 9. 虚拟经济与收藏规则

### 9.1 钱包

钱包必须保存余额、累计收入、累计支出和不可重复的交易流水：

```json
{
  "wallet": {
    "balance": 1284,
    "totalEarned": 3821,
    "totalSpent": 2537,
    "transactions": [
      {
        "id": "tx_game_muyu_session_abc123",
        "type": "earn",
        "source": "game:muyu",
        "amount": 18,
        "createdAt": "2026-08-13T15:35:10+08:00"
      }
    ]
  }
}
```

- 每个游戏结算用 `sessionId` 生成唯一交易 ID，重复提交不重复加币。
- 购买操作同时校验余额、扣款、写入拥有状态，必须一次成功或全部失败。
- 不需要复杂反作弊，但需要避免双击、窗口重载和崩溃造成重复奖励。

### 9.2 首发价格与节奏

| 商品层级 | 建议价格 | 正常获得时间 |
|---|---:|---|
| 小配件 / 数字样式 | 150–250 | 2–4 天 |
| 悬浮窗 / 中级主题 | 400–600 | 5–8 天 |
| 高级主题 | 900–1200 | 10–16 天 |
| 套装 | V1.1 再定 | 不进入首发 |

按每天 3–5 局、60–100 币计算。首发应赠送 80–120 币，让用户在第一次游戏后就能完成一次购买，验证闭环。

### 9.3 商品规则

```json
{
  "id": "capybara-pajamas",
  "type": "capybaraAccessory",
  "name": "睡衣卡皮巴拉",
  "price": 200,
  "rarity": "common",
  "previewAsset": "store/capybara-pajamas.webp",
  "assetBundle": "capybara/pajamas",
  "availability": "shop"
}
```

- 商品类型只允许 `theme`、`floating`、`capybaraAccessory`、`effect`。
- 成就限定商品 `availability: achievement`，不显示价格。
- 主题、悬浮窗和角色配件分别装备，不互相覆盖。

### 9.4 称号与摸鱼率

- 摸鱼率仍按 `slackSeconds / workSeconds` 计算，用于当日/周幽默评价。
- 当前按“摸鱼金额 ÷ 日薪”生成的称号不再作为长期称号来源，因为它会让相同行为因薪资不同得到不同身份。
- 长期称号由明确成就授予，如累计摸鱼时间、Combo、反应成绩、图鉴进度。
- 对旧用户可授予“早期摸鱼员”纪念称号，保留情感连续性。

## 10. 数据与技术架构建议

### 10.1 状态仓库

首发建议：一个由 Electron 主进程独占写入的版本化状态仓库，内部按领域分区：

```json
{
  "schemaVersion": 2,
  "settings": {},
  "profile": {
    "wallet": {},
    "titles": [],
    "equippedTitle": null
  },
  "inventory": {
    "ownedItems": [],
    "equipped": {}
  },
  "history": [],
  "slackSessions": [],
  "gameProgress": {},
  "achievements": {}
}
```

原因：钱包扣款和库存新增需要原子一致，过早拆成多个 JSON 会增加中途崩溃后的不同步风险。若历史数据增长明显，可在保持仓库接口不变的前提下把历史迁到 SQLite。

必须具备：

- 临时文件写入 + `rename` 的原子保存。
- 最近一次成功文件备份。
- `schemaVersion` 与逐版本迁移函数。
- 读取失败时恢复备份，不静默覆盖用户数据。
- 所有写操作集中在主进程；渲染进程只发领域命令。

### 10.2 IPC 与窗口安全

当前主窗和悬浮窗应从：

```text
contextIsolation: false
nodeIntegration: true
```

迁到：

```text
contextIsolation: true
nodeIntegration: false
preload: 暴露白名单 API
```

白名单示例：

- `state.getSnapshot()`
- `mode.enterSlack()` / `mode.exitSlack()`
- `game.open(gameId)` / `game.complete(result)`
- `shop.purchase(itemId)`
- `inventory.equip(itemId)`
- `window.minimizeToFloat()`

渲染进程不能传任意文件路径或任意配置键给主进程。

### 10.3 游戏协议

```json
{
  "sessionId": "game_muyu_20260813_xxx",
  "gameId": "muyu",
  "startedAt": "...",
  "endedAt": "...",
  "score": 426,
  "metrics": {
    "maxCombo": 37,
    "criticalHits": 8
  },
  "reward": 18
}
```

主进程负责：生成会话、确认未结算、计算或校验奖励、写钱包流水、更新日记录。游戏窗口只负责玩法和展示。

### 10.4 主题架构

现有 CSS 变量可保留，但需要从颜色变量扩展为语义 token：

```text
--color-canvas
--color-panel
--color-panel-elevated
--color-text-primary
--color-text-secondary
--color-accent
--color-success
--color-danger
--color-border
--shadow-card
--radius-card
--font-numeric
--asset-dashboard-bg
--asset-jar
```

主题 manifest 只引用允许的 token 和已打包资源，不允许注入任意 CSS/HTML。

### 10.5 老板键

- 主进程用 Electron `globalShortcut` 注册，默认 `Ctrl/Cmd + Shift + M`。
- 设置中允许修改并检测冲突。
- 触发后隐藏所有游戏/摸鱼屋窗口，悬浮窗切到极简计薪样式。
- 再次触发只恢复本应用此前可见窗口。
- 应用退出或快捷键修改时必须注销旧快捷键。

### 10.6 记录补全

现有每日记录基础上新增：

```json
{
  "date": "2026-08-13",
  "salary": 286.42,
  "workSeconds": 25120,
  "slackSeconds": 3280,
  "slackRate": 0.1306,
  "gameCount": 6,
  "fishCoinsEarned": 82,
  "fishCoinsSpent": 200
}
```

`workSeconds` 需要明确口径：建议为班次窗口内应用运行且未暂停统计的秒数；摸鱼秒数是其中的子集，不能在周汇总时重复相加。

## 12. 素材交付标准

### 12.1 图像与动画

- 透明角色、道具：PNG，sRGB，直通 Alpha，禁止残留白边/黑边。
- 大背景：优先 WebP/AVIF，保留无损 PSD/PSB 母版。
- 角色统一 512×512 或 1024×1024 画布，底部中心锚点一致。
- PNG 序列文件名：`capybara_work_0001.png`。
- atlas 必须带帧尺寸、锚点、持续时间和是否循环。
- 每个动效提供减少动态效果的静帧。
- 商品预览必须使用真实 UI 截图合成，不能只给抽象色块。

### 12.2 音频

- 母版 WAV 48kHz / 24-bit；应用版 OGG。
- 短音效前后无多余静音；循环音首尾无爆点。
- 每条文件附授权与来源信息。
- 默认静音或低音量；关键状态不能只靠声音表达。

### 12.3 字体与图标

- 继续复用现有 Phosphor 图标，缺失图标再补同风格资源。
- 像素主题若使用专用字体，必须确认桌面应用嵌入和商用授权。
- 不使用 emoji 作为正式货币、商品或游戏资产；emoji 只能出现在文案草稿中。

### 12.4 命名与版本

```text
assets/
  characters/capybara/{state}/{frame}.png
  games/muyu/...
  games/boss-alert/...
  games/desk-fishing/...
  themes/{themeId}/manifest.json
  store/previews/{itemId}@2x.webp
  audio/{domain}/{event}.ogg
```

- 所有 ID 使用小写 kebab-case。
- 资源文件不使用中文、空格和“最终版2”式命名。
- manifest 带 `assetVersion`，缓存更新不依赖改文件名猜测。

## 15. 风险与决策点

### 开发前必须确认的 8 个决策

1. 品牌是否继续使用“挣点窝囊费”。建议：继续使用。
2. 是否接受四个一级入口。建议：接受。
3. V1A 是否只做木鱼暴击和 3 件商品。建议：接受。
4. 星轨弹射是否降级为彩蛋。建议：接受并保留存档。
5. 默认模式是否从 UI 隐藏。建议：隐藏，兼容旧数据。
6. 卡皮巴拉首发配件采用“可换装 overlay”还是每套重画。建议：先做配件 overlay，完整服装后置。
7. 数据继续 JSON 还是改 SQLite。建议：先做原子、版本化统一 JSON 仓库，保留仓库接口便于后迁移。
8. 首发是否完全离线。建议：是。

### 主要风险

- **范围风险**：三款游戏、商城、收藏、任务、成就同时开发，会让首个可验证闭环过晚出现。
- **美术风险**：卡皮巴拉没有统一画布和动作骨架时先做衣服，会产生指数级返工。
- **数据风险**：钱包和库存分文件、非原子写入，容易在崩溃后出现“扣了币但没商品”。
- **体验风险**：自动弹游戏、频繁提醒和奖励倍率事件会破坏桌面工具的安静感。
- **品牌风险**：直接改名为功能化的“摸鱼计薪”会损失当前名称的记忆点。
- **安全风险**：继续扩大 `nodeIntegration` 渲染面会放大本地文件和 IPC 风险。
- **可访问性风险**：高频点击和快速反应玩法如果没有替代操作，会排除部分用户。
- **包体风险**：当前 `assets` 已约 17MB；三款游戏和逐帧换装会快速增长，必须使用 atlas、WebP/OGG 和资源预算。

## 16. 推荐的下一步顺序

1. 决定上面 8 个产品决策。
2. 先画 5 张关键稿：摸鱼看板、悬浮窗摸鱼态、摸鱼屋、木鱼暴击、购买并装备成功。
